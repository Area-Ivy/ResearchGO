一、项目目的

随着大语言模型和检索增强生成（RAG）技术的快速发展，科研人员在论文检索、阅读和知识管理方面的需求不断提升。传统学术检索平台多以关键词匹配和简单文献列表展示为主，缺乏对论文内容的深度理解与交互式问答支持，难以满足研究者在有限时间内高效获取关键信息的需求。
ResearchGO 智能学术研究助手项目旨在构建一个基于微服务架构的高可用学术研究平台，集成混合检索 RAG、AI 智能体（Agent）、论文管理与分析等功能，为用户提供一站式学术信息服务体验。

我们的系统可以：
①提供一站式学术服务，包括学术文献检索、个人论文库管理、论文问答、分析报告与思维导图生成，提高科研用户的文献处理效率。
②整合大语言模型与混合检索技术，通过向量检索、BM25 稀疏检索、RRF 融合与重排序，实现对本地论文库和开放学术数据库的高精度检索与问答服务。
③通过微服务架构与消息队列，对论文上传、向量索引、Agent 调用等流程进行解耦与异步处理，提升系统可扩展性和稳定性，保障用户长期使用体验。

二、项目范围

ResearchGO 智能学术研究助手面向高校学生、科研人员与技术从业者，支持对个人论文库和外部学术资源进行统一管理和智能检索。用户可以在系统中上传 PDF 论文，由系统自动完成存储与结构化解析，并建立语义索引，随后通过自然语言对话的方式进行论文内容问答与多篇论文对比分析。同时，系统提供对接开放学术数据库（如 OpenAlex）的文献检索功能，帮助用户在更大范围内发现相关研究成果。

系统还提供用户认证、权限控制与数据隔离能力，确保不同用户的论文与对话数据互相独立；管理员可以进行基础配置管理与系统监控。总体而言，我们旨在提供与学术研究相关的便捷服务与信息管理能力，从而提升用户在文献检索、阅读与整理过程中的体验，满足日常科研活动中对高效信息获取的需求，并确保系统的高效运营与后续扩展。

总结如下：
用户模块：用户能够注册登录、管理个人信息和个人论文库，上传和管理 PDF 论文，基于论文内容进行语义检索和问答，使用 AI 生成论文分析报告和思维导图，并可通过聊天界面与智能体进行多轮学术对话。
管理员模块：进行基础系统配置管理，如用户管理、服务状态查看与公告发布（如系统更新说明、维护通知等）。
系统服务模块：为系统提供文献检索、向量搜索、论文存储与分析、思维导图生成等后台服务能力，并支持任务异步处理与性能监控。

三、主要功能及需求分析表

3.1 普通用户

文献检索与浏览：能够通过系统对接的开放学术数据库（如 OpenAlex）进行论文检索，按关键词、年份、引用量等条件筛选，并查看文献基本信息。
个人论文库管理：支持用户上传 PDF 论文，自动完成论文存储与结构化解析，构建个人可检索论文库。
论文内容问答与分析：支持基于单篇或多篇论文的内容问答、要点提取、摘要生成，以及思维导图与分析报告的生成。

3.2 管理员

系统配置与用户管理：管理员能够管理系统基础配置，查看服务运行状态，并对用户账号进行必要的管理操作。
公告与文档维护：管理员可发布系统公告、更新说明与使用指引文档，方便用户了解系统变更与使用方式。

3.3 系统服务与后台任务

异步任务处理：系统通过消息队列对论文上传、向量索引、批量分析等耗时操作进行异步处理，保证核心交互过程的流畅性。
向量检索与混合检索：后台服务负责构建 Milvus 向量索引与 BM25 稀疏索引，实现 Dense+Sparse 混合检索与重排序。

四、初步逻辑架构

在架构设计阶段，我们根据微服务架构与领域驱动设计（DDD）的基本思想，将系统划分为若干职责单一的服务，保证高内聚和低耦合。首先从整体业务上划分为智能体服务、用户与认证服务、会话管理服务、论文存储服务、向量检索服务、文献检索服务、思维导图服务以及论文分析服务等子域；再结合基础设施与网关层，形成完整的端到端调用链路。

在当前阶段，我们采用前后端分离的单页 Web 应用架构，前端基于 Vue 3 + Vite，主要负责页面展示与前后端交互；后端以 FastAPI 为基础框架，按照业务场景拆分为多个独立微服务，并通过 Traefik 作为统一 API 网关进行请求路由和负载管理，结合 Consul 实现服务注册与发现。

各微服务通过 MySQL、MinIO、Milvus、Redis、RabbitMQ 等基础设施提供持久化存储、对象存储、向量索引、缓存与消息队列能力。目前我们已完成基础服务划分与主要接口设计，并通过 Docker Compose 进行整体编排部署。后续将根据开发过程中的性能与复杂度情况，对服务粒度与边界进行适当微调。

五、候选开发技术

根据以上微服务架构，我们拟开发一个基于 Web 的学术研究助手应用程序。我们总结了以下候选开发技术栈，后续将根据实际开发进展进行选型或组合使用：

前端：Vue 3、Vite、Vue Router、Axios
后端：FastAPI、LangGraph、LangChain
数据库与存储：MySQL / PostgreSQL（关系型）、MinIO（对象存储）
向量数据库：Milvus / Qdrant
缓存与会话：Redis
消息队列：RabbitMQ / Kafka
API 网关与服务发现：Traefik / Nginx，Consul / Nacos
容器化与编排：Docker / Docker Compose / Kubernetes（后期可扩展）

六、中间件

中间件处于软件架构中的枢纽位置，它提供了各种核心服务，连接和调节不同软件之间的交互。以下是我们在后续开发过程中拟使用的中间件：

服务注册中心：用于服务注册与发现，如 Consul、Nacos 等。
配置中心：用于集中管理各服务的配置信息，如 Consul KV、Spring Cloud Config、Apollo 等。
API 网关：用于请求路由、过滤、限流等，如 Traefik、Nginx 等 API 网关。
服务调用：用于服务间的调用，暂以 RESTful API 为主，后续可视情况引入 gRPC 等方式。
负载均衡：用于在多个服务实例间分配请求负载，如 Traefik、Nginx 等。
消息队列：用于服务间的异步通信解耦，处理论文解析与索引构建等耗时任务，确保高并发下的系统响应性，如 RabbitMQ、Kafka 等。
数据库访问组件：用于数据库访问、连接池与 ORM 支持，如 SQLAlchemy 等。
身份认证：用于服务间认证和授权，保证安全的用户访问和身份验证，如 JWT 等。
数据序列化：用于服务间通信与数据传输，如 JSON 等。

七、平台

我们考虑到承载该应用的基础设施、开发工具集以及可能涉及的第三方服务集成，列举了我们已经在使用或后续开发可能会涉及到的一些平台：

微服务与云原生平台：
基于 Docker Compose 的本地多服务编排环境，后续可迁移到 Kubernetes 等云原生平台。通过 Traefik 与 Consul 组合，为各微服务提供服务发现、动态路由与基础弹性扩展能力。

云服务平台：
阿里云、腾讯云等云服务提供商，可为后续线上部署提供计算、对象存储、数据库与监控服务，降低自建基础设施成本。

容器化和编排平台：
• Docker：用于打包各个微服务及基础组件，保证在不同环境中的一致运行。
• Kubernetes（可选）：作为后期扩展方向，用于自动化容器部署、扩缩容与负载均衡。

开发与协作平台：
• GitHub / Gitee：用于项目代码托管、Issue 管理与 CI/CD 集成。
• 团队协作工具（如 飞书 / 钉钉）：支持即时通讯、会议、文档共享等功能，适用于团队协作和沟通。

这些平台有利于团队协作、文档及代码共享、版本控制和自动化部署。
